Qué es el DOM y por qué no es el archivo HTML

Cuando abres una página, el navegador interpreta el documento y construye una representación en memoria. El DOM, Document Object Model, ofrece objetos y relaciones para consultar esa estructura y modificarla. JavaScript puede trabajar con esos objetos para añadir comportamiento a contenido que ya existe.

El archivo HTML es una entrada; el DOM representa el documento interpretado en un momento concreto. El navegador puede corregir ciertas estructuras al analizarlas y un script puede modificar elementos después. Por eso mirar el archivo original no siempre muestra el mismo estado que inspeccionar la página mientras la utilizas.

Imagina un encabezado que cambia al pulsar un botón. El script no necesita reescribir el archivo en tu disco: modifica un objeto del documento cargado y el navegador refleja el nuevo estado. Al recargar, se vuelve a cargar el documento y esa modificación temporal no se conserva automáticamente.

Idea clave

El DOM es un modelo de objetos del documento, con una estructura de árbol. HTML aporta la estructura inicial; JavaScript utiliza las APIs del DOM para consultar y cambiar el documento en memoria.

Antes de añadir comportamiento, conviene comprender cómo organizar HTML con encabezados y regiones semánticas. Modificar una página no elimina la necesidad de que su estructura tenga sentido.

Nodos, elementos y document: reconocer el árbol

Un árbol tiene relaciones entre padres, hijos y hermanos. Un main puede contener un h1 y un párrafo; ambos comparten padre. Los elementos representan etiquetas, pero no todos los nodos son elementos: el texto dentro de un encabezado también es un nodo, y los comentarios constituyen otro tipo.

Este esquema simplifica un documento para hacer visibles las relaciones. No muestra todos los nodos, como los espacios en blanco que pueden convertirse en nodos de texto. Esa distinción importa cuando compares herramientas que recorren todos los nodos con otras que trabajan únicamente con elementos.

document es la referencia al documento actual dentro del entorno del navegador. Desde ella puedes buscar elementos sin escribir manualmente todo el camino desde html hasta main. No es una variable que tengas que crear con const: el entorno ya la proporciona.

El DOM es una API de la plataforma web, no una palabra reservada nueva del lenguaje JavaScript. Una operación sobre document necesita el entorno adecuado y un documento cargado. Ejecutar el mismo código en otro entorno que no tenga document no crea una página por arte de magia.

Seleccionar con querySelector y querySelectorAll

document.querySelector recibe un selector CSS y devuelve el primer elemento coincidente, o null si no encuentra ninguno. Para un ID escribe el prefijo #; para una clase, un punto. El selector debe ser válido y el ID debe coincidir con el HTML.

querySelectorAll devuelve una NodeList estática de los elementos coincidentes. Si no hay coincidencias, es una colección vacía. Puedes recorrerla con forEach, pero no debes asumir que ofrece todos los métodos de un Array.

Estática significa que la lista no añade automáticamente nuevos resultados si después insertas otro elemento coincidente. Sus elementos siguen siendo referencias a objetos, por lo que puedes modificarlos; lo que no se recalcula solo es la pertenencia a esa lista. Si necesitas una selección actualizada, realiza de nuevo la consulta.

La documentación de querySelector y querySelectorAll permite contrastar esos retornos. No son dos formas equivalentes de obtener exactamente el mismo tipo de resultado.

Guardar una referencia en const impide reasignar esa variable; no congela el elemento. Puedes cambiar su texto o clases utilizando la referencia sin sustituir el valor de la variable. Esa es la operación que realizaremos con el título del ejemplo.

Leer y modificar texto con textContent

textContent permite consultar el contenido textual de un nodo. En un encabezado sencillo devuelve su texto. Al asignarle una cadena, sustituyes su contenido por texto; no le estás pidiendo al navegador que interprete etiquetas HTML incluidas en esa cadena.

Si un elemento contiene hijos, asignar textContent también reemplaza esos hijos. Por ejemplo, un título con una palabra dentro de strong perdería ese marcado al reemplazar todo su contenido por texto. Selecciona un nodo más específico si quieres conservar partes de una estructura.

Evita utilizar innerHTML cuando solo quieres mostrar texto. Además de introducir una operación distinta, interpretar HTML exige especial cuidado con cadenas que puedan venir de personas o fuentes externas. En este ejercicio basta con una cadena fija y textContent.

Cambiar el texto modifica la página cargada sin escribir el archivo original. Compruébalo en el panel Elements y luego recarga: el título inicial volverá a aparecer hasta que se ejecute de nuevo el cambio. Esa prueba hace visible la diferencia entre fuente y estado actual.

Cambiar clases y atributos sin mezclar responsabilidades

Una clase conecta el estado de un elemento con reglas CSS. Con classList.add añades una clase, con remove la retiras y con toggle alternas su presencia. Puedes preguntar si existe mediante contains. El nombre se escribe sin el punto del selector CSS.

El script decide que el título está destacado y la hoja de estilos decide cómo se ve ese estado. Así no necesitas repetir colores dentro de JavaScript. Añadir una clase sin una regla CSS correspondiente es válido, pero no produce necesariamente un cambio visual.

setAttribute establece el valor de un atributo; getAttribute permite leerlo. Aquí usamos data-estado para practicar con un dato propio del elemento. No inventes atributos ARIA para decorar ni los cambies sin comprender el estado que comunican a tecnologías de asistencia.

Los atributos y las propiedades del objeto están relacionados, aunque no siempre se comportan igual. En un formulario, por ejemplo, el valor actual de un campo se consulta normalmente con su propiedad value. Para este primer ejercicio trabajaremos con texto, una clase y un atributo de datos explícito.

Eventos: registrar una respuesta con addEventListener

Un evento describe algo que ocurre, como activar un botón o escribir en un campo. addEventListener registra una función que se ejecutará cuando llegue el evento indicado. Registrar esa función no equivale a ejecutar su cuerpo inmediatamente.

El primer argumento es el nombre del evento, click, sin el prefijo on. El segundo es una función. La forma () => { ... } crea la función que contiene la respuesta. Si utilizas una función con nombre, entrega la referencia; escribir paréntesis para llamarla en ese lugar ejecutaría otra operación.

Usa un button nativo para la acción. Su activación funciona con mouse y con teclado, sin convertir un div en un control incompleto. No necesitas escuchar teclas adicionales para reproducir el comportamiento que el botón ya proporciona.

La referencia de addEventListener describe el registro de listeners. Mantén un solo registro inicial para esta interacción; añadir nuevos listeners cada vez que se pulsa el botón puede acumular respuestas innecesarias.

Errores comunes: null, selectores y carga

Un null indica que esa búsqueda no encontró un elemento. Revisa el selector, la coincidencia del ID y el momento de ejecución. No soluciones el problema añadiendo un tiempo de espera arbitrario: eso puede ocultarlo en tu equipo y volver a fallar con otra velocidad de carga.

Error común

Llamar addEventListener sobre null porque el botón todavía no existe o su ID no coincide. Comprueba la selección y la carga del script antes de intentar modificar el documento.

Si falta un elemento, el ejemplo informa del problema en la consola y evita operar sobre referencias nulas. Esa comprobación no corrige el HTML por ti: hay que localizar y reparar la causa. Tampoco captura selectores inválidos; un selector mal formado puede lanzar una excepción en la propia consulta.

Lo que debes recordar

Lo que debes recordar

El DOM representa el documento en memoria. Document permite consultar elementos; querySelector devuelve el primero o null y querySelectorAll una NodeList estática. TextContent cambia texto, classList gestiona clases y addEventListener registra respuestas a eventos.

Selecciona, comprueba y después modifica. Con una estructura HTML clara y una interacción pequeña puedes identificar qué cambia, cuándo cambia y qué debería ocurrir si no encuentras los elementos esperados.
